# اجرای تخصصی ۹ ایجنت پیمانکاری صبا VIP

این فایل مخصوص همین مخزن Flutter است و به پروژه‌های دیگر ارتباطی ندارد.

## دو نوع اجرای مستقل

### ۱) اجرای واقعی AI از طریق Codex CLI

پیش‌نیاز: مخزن روی رایانه/محیط Codex باز باشد؛ Codex CLI نصب و کاربر وارد حساب شده باشد. مدل یا اعتبار مصرفی طبق حساب میزبان است؛ این برنامه هیچ API key یا سرویس پولی جدیدی ایجاد نمی‌کند.

از ریشه همین مخزن:

- فهرست مأموریت‌ها: `python3 tool/run_agent_team.py list`
- برنامه اجرایی بدون مصرف اعتبار: `python3 tool/run_agent_team.py plan expense-settlement`
- شروع بررسی **فقط خواندنی**: `python3 tool/run_agent_team.py run expense-settlement --execute`
- شروع پیاده‌سازی با مجوز تغییر فایل‌های همین مخزن: `python3 tool/run_agent_team.py run expense-settlement --execute --write`

برای دو مأموریت دیگر به‌جای `expense-settlement` از `release-audit` یا `ui-improvement` استفاده کن.

اجرا فقط با `--execute` آغاز می‌شود؛ مسیر اجرایی بدون Codex CLI، خطا می‌دهد و موفقیت ساختگی اعلام نمی‌کند. حالت نوشتن به پوشه Git تمیز نیاز دارد؛ استفاده از sandbox خطرناک و دسترسی سراسری فعال نیست. گواهی امضا و secret تغییر نمی‌کند. Codex باید در یک جلسه مأموریت را بین متخصص‌ها واگذار کند؛ اگر میزبان subagent ندارد، باید صریح گزارش شود.

### ۲) اجرای واقعی کنترل‌های آفلاین بدون AI

- اجرای ۹ کنترل تخصصی قابل سنجش: `python3 tool/specialist_checks.py`
- گزارش JSON برای CI: `python3 tool/specialist_checks.py --output dist/SPECIALIST_QA.json`
- فقط کنترل حسابداری: `python3 tool/specialist_checks.py --role accounting_agent`

این‌ها **اجرای خود ایجنت هوش مصنوعی نیستند**؛ یک مجموعه بررسی محدود، تکرارپذیر و رایگان است که ۹ حوزه تخصصی را پوشش می‌دهد. گزارش آن‌ها عبارت `deterministic-specialist-qa-not-ai-agents` دارد تا با مأموریت AI اشتباه نشود.

در GitHub Actions این بررسی‌ها پیش از ساخت APK اجرا می‌شوند. تست‌های Flutter (`flutter analyze` و `flutter test`) و تأیید امضا در مراحل مستقل و قبلی همان workflow باقی مانده‌اند. کنترل ایستای UI و اجرای EXPLAIN QUERY PLAN به‌جای آزمون واقعی نمایش، سرعت گوشی یا امنیت کامل نیستند.

## مدیریت تیم

| فاز | متخصص‌های فراخوانده‌شده | شرط تحویل |
|---|---|---|
| بازبینی مستقل | accounting_agent، database_agent، ui_designer | گزارش دقیق از سورس و سناریوهای نقص |
| اجرای تغییرات | app_developer؛ فقط یک نویسنده مشترک | کد و تست‌های همسو با منطق مالی |
| ارزیابی مستقل | testing_agent، security_agent، performance_agent | نتایج آزمون، خطر امنیتی و معیار سرعت |
| تحلیل خطا | debugger_agent (فقط هنگام خطای واقعی) | علت ریشه‌ای و آزمون تکرار خطا |
| نسخه اندروید | android_release | صحت امضا، هش، نسخه و آزمون نصب در صورت دسترسی به دستگاه |

حداکثر سه ایجنت به‌صورت هم‌زمان و فقط برای بازبینی‌های مستقل؛ روی فایل‌های مشترک مالی و پایگاه‌داده نویسنده هم‌زمان وجود ندارد.

## محدودیت‌های صادقانه

- ساخت فایل ایجنت، **راه‌اندازی مداوم یا اجرای خودکار Codex در GitHub نیست**. برای اجرای AI باید خود Codex CLI یا جلسه Codex متصل به این مخزن را فعال کنی.
- GitHub Actions فقط آزمون و ساخت را با دستورهای قطعی اجرا می‌کند و کلید API مدل دریافت نمی‌کند.
- تست موفق بدون گوشی، آزمون نصب و کارکرد واقعی اپ روی اندروید محسوب نمی‌شود.
- استقلال این پروژه از سایر پروژه‌ها باید در تمام مأموریت‌ها حفظ شود.
